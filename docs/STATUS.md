# 验证状态

版本 `0.1.0` 尚未发布。运行 `npm test` 会构建核心和两个适配器，并验证模拟宿主、传输、桌面渲染和状态文件。测试不会连真实机器人。

## 手机任务控制验证

模拟宿主测试覆盖接收确认、状态与耗时、停止当前任务并保留后续消息、交互撤销、群内归属、清除落盘及去重、重启未知状态、状态写入失败、超时未知、配额耗尽后的控制命令，以及分条重试保留未确认投递。

2026-11-17 在 mini 的 DSH `0.2.2-rc.3` Web profile 上验证了微信接收确认、`/help`、`/status` 的「等待回答」，以及 `/cancel` 得到宿主确认后回送「已取消」。等待编号回答时发送的普通文字收到了答复格式提示，排队数量仍为零。另一次测试在前序任务执行期间发送了第二条任务，微信确认排队，`/status` 显示排队 1 条，前序任务自然结束后第二条任务执行并回送结果。Telegram 尚未做真实账号验证。

## 真机证据

后续在 mini 的微信聊天中确认了 `/cancel` 只取消当前任务。排队中的下一条任务继续执行并在微信返回结果。另一次测试中，`/clear` 清除了 1 条排队消息，当前任务继续运行，随后单独通过 `/cancel` 停止。被清除的消息保留了清除回执，未执行或返回任务结果。微信投递流水也记录了合并重复结果预览后的 `/status` 发送成功。

长任务提醒也已在 mini 的微信通道验证。任务开始约 60 秒后收到一次提醒，约 123 秒后在原聊天收到最终回复。截图和投递流水均确认提醒已送达。

## 已知限制

- 同一个聊天只有一个活动的交互提示。曾观察到桌面返回空答案集后抢先结束提问；聊天不能区分桌面跳过与真正的空答案。
- 宿主没有工作区登记服务或登记失败时，会话可能出现在 **Ungrouped**。
- 每通道只运行一个账号实例。限流计数能持久化，但不协调并发运行的多个实例。
- 持久收件箱恢复尚未开始的普通消息；已开始的回合不会自动重跑。平台响应不明确时，出站重试仍可能重复。重放与去重行为见[运维指南](OPERATIONS.md#状态和重试)。
- 目前只支持一次性审批，视频不抽帧，PDF 正文需要可选解析器。语音和模型依赖的安装方法见[运维指南](OPERATIONS.md#语音转写)。
