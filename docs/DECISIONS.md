# 决策记录

这里记录设计理由和代价。当前行为见[设计](DESIGN.md)，验证范围见[验证状态](STATUS.md)。

## ADR-1：从平台无关的核心开始

早期的 `dsh-plugin-weixin` 是参考实现。新插件保留聊天驱动 agent 的路径，把账号和传输交给适配器。旧插件的记忆、预算和生活状态不在迁移范围内。

## ADR-2：首次启动也要显式授权

聊天消息可能触发工具，不能把权限给第一个发来消息的人。空白名单默认拒绝。代价是首次安装需要从拒绝日志核对 ID，再手动授权。

## ADR-3：只有核心是 bundle

统一管理生命周期可避免增加通道时留下一条额外的宿主加载器记录。适配器按包名导入，卸载时从 `adapters` 移除。桌面渲染器仍需显式注册（ADR-9）。

## ADR-4：会话 ID 由地址派生

同一通道、账号和聊天在重启后应接回原会话。`/new` 通过保存线号来另开会话。账号键变更会开启一条新会话线，因此账号键必须独立于显示名称；旧键需要显式迁移。

## ADR-5：交互答复直接处理

正在运行的回合可能等审批结果。把答复放进普通回合队列会让双方互等。答复走独立分流，但仍先检查权限；桌面与手机共用同一次交互，不各自完成一次。

## ADR-6：配额跨重启保存

使用宿主 `channels` 存储域，没有域时回落到 `counters.json`。配额检查需要同步读取；存储提供持久性，不能协调多个实例同时检查和扣减。预留留在内存，避免未开始的回合在重启时消耗额度。

## ADR-7：发送前后都写流水

只在发送成功后记一行，进程中断时会丢失整次尝试。用同一投递 ID 记录 `sending` 和 `settled`，让无结果的尝试保持为未知状态。重发继续使用该 ID。

## ADR-8：状态卡片用宿主 HTTP 路由

浏览器的 Typert Remote 依赖构建期生成的工件，运行中注册的 namespace 不足以让浏览器调用。卡片用宿主同源路由，写入要求 `Origin` 匹配；该检查不能替代访问控制。部署时保留宿主管理界面的访问限制。

## ADR-9：客户端显式注册 Chat 行

浏览器不能直接读取运行中的适配器注册表。新增通道要在 `client.js` 的 `CHANNELS` 表添加一项；这样新渲染器的通道标识和徽标都能在客户端构建中确定。

## ADR-10：可选宿主服务各自降级

启动时通过注入获取存储、工作区等可选外部服务；运行时也按具体调用点读取宿主服务。缺少可选服务不应卡住启动。宿主包按可选 peer 使用，避免插件安装时带入一套不同的宿主依赖。

## ADR-11：单条消息失败不结束通道

预期的发送失败通过结果对象表达，普通文本回复可以重试；下载或转写失败时保留仍可用的消息内容。初始化及网络层仍可能抛错，由各自的调用方记录日志或退避，避免把单次失败变成通道停摆。
