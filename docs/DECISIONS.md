# 决策记录

这里记录设计理由和代价。当前行为见[设计](DESIGN.md)，验证范围见[验证状态](STATUS.md)。

## ADR-1：从平台无关的核心开始

早期的 `dsh-plugin-weixin` 是参考实现。新插件保留聊天驱动 agent 的路径，把账号和传输交给适配器。旧插件的记忆、预算和生活状态不在迁移范围内。

## ADR-2：首次启动也要显式授权

聊天消息可能触发工具，不能把权限给第一个发来消息的人。空白名单默认拒绝。代价是首次安装需要从拒绝日志核对 ID，再手动授权。

## ADR-3：只有核心是 bundle

统一管理生命周期可避免增加通道时留下一条额外的宿主加载器记录。适配器按包名导入，卸载时从 `adapters` 移除。桌面渲染器仍需显式注册（ADR-9）。

## ADR-4：会话 ID 由地址派生

同一通道、账号和聊天在重启后应接回原会话。`/new` 通过保存线号来另开会话。账号键变更会开启一条新会话线，因此账号键必须独立于显示名称；旧键需要显式迁移。

## ADR-5：交互答复直接处理

正在运行的回合可能等审批结果。把答复放进普通回合队列会让双方互等。答复走独立分流，但仍先检查权限；桌面与手机共用同一次交互，不各自完成一次。

## ADR-6：配额跨重启保存

使用宿主 `channels` 存储域，没有域时回落到状态库的 `counters` 段；旧 `counters.json` 只用于一次性迁移并归档。配额检查需要同步读取；状态根通过单写者锁限制为一个进程，但共享宿主域的不同状态根仍不能协调配额检查和扣减。预留留在内存，避免未开始的回合在重启时消耗额度。

## ADR-7：发送前后都写流水

只在发送成功后记一行，进程中断时会丢失整次尝试。用同一投递 ID 记录 `sending` 和 `settled`，让无结果的尝试保持为未知状态。重发继续使用该 ID。

## ADR-8：状态卡片用宿主 HTTP 路由

浏览器的 Typert Remote 依赖构建期生成的工件，运行中注册的 namespace 不足以让浏览器调用。卡片用宿主同源路由，写入要求 `Origin` 匹配；该检查不能替代访问控制。部署时保留宿主管理界面的访问限制。

## ADR-9：客户端显式注册 Chat 行

浏览器不能直接读取运行中的适配器注册表。新增通道要在 `client-src/channels.js` 的 `CHANNELS` 表添加一项并重新构建 `client.js`；这样新渲染器的通道标识和徽标都能在客户端构建中确定。

## ADR-10：可选宿主服务各自降级

启动时通过注入获取存储、工作区等可选外部服务；运行时也按具体调用点读取宿主服务。缺少可选服务不应卡住启动。宿主包按可选 peer 使用，避免插件安装时带入一套不同的宿主依赖。

## ADR-11：单条消息失败不结束通道

预期的发送失败通过结果对象表达，普通文本回复可以重试；下载或转写失败时保留仍可用的消息内容。初始化及网络层仍可能抛错，由各自的调用方记录日志或退避，避免把单次失败变成通道停摆。

## ADR-12：状态库用 SQLite 的段表，而不是逐实体拆表

状态写入需要「多段一起提交」的原子性，而读者总是整段加载；文档上限（500 条入站、100 条计划）远低于行级索引才有收益的规模。因此 `state.db` 用 `sections(name, json)` 保存经过 schema 校验的七个段，一次 `writeMany` 是一个事务。代价是不能用 SQL 做局部更新；收益是删掉了整份 JSON 重写、v1/v2 迁移、镜像与双文件锁，且保留了已有的 schema 校验。旧状态在首次打开时导入并归档，数据库与 WAL 文件保持 0600。

## ADR-13：飞书协议栈保持手写，不引入官方 SDK

评估过 `@larksuiteoapi/node-sdk` 1.76.0：它覆盖长连接、事件分发、卡片回调与 REST，能替掉 `socket.ts` + `proto.ts` 约 570 行。但它带 84 个传递依赖、约 41MB，且我们只需其中很窄的一部分（一条长连接 + 五个 REST 调用）；包装它仍要自己实现 `IngressSink` 的确认语义。现有手写栈已在真实网关上验证过分片、确认、重连和 Blob 陷阱，并由 `feishu-handoff` 测试覆盖。决定保留手写实现，把 `socket.ts` 与 `proto.ts` 作为可替换边界；若网关协议再次变化或需要新的回调类型，再按此评估迁移。
