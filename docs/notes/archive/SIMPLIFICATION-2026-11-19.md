# 精简结论（2026-11-19）

目标是把通道维持为可信的聊天入口和投递边缘。当前已完成五项精简：

1. 适配器只有 `startWithSink`，移除旧订阅入口、处理器集合和废弃能力字段。
2. 移除旧输出目录模式和提示词；文件由 `present` 或独立本地 Markdown 图片声明。
3. 手机只保留项目选择和 `/new`；历史会话在桌面查看。旧 `/sessions`、`/session` 只返回迁移提示，防止被当成模型任务。原会话选择、最大编号与排队消息快照保持。
4. 产物索引直接来自捕获成功的文件名，投递和恢复按索引读取。删除通用递归扫描器、两次重复目录枚举以及仅测试旧扫描规则的测试。保留逐项包含校验、指纹和私有上传快照。

5. 手机 `/status` 聚焦任务与队列，不再读取 journal 合并最近发送预览。最近发送预览继续由桌面状态卡提供，诊断流水与入站去重不变。

附件发送顺序与索引编号一致，新索引按文件名排序，历史索引保持原顺序。附件数量统一遵循既有持久层的 100 文件边界，配置允许 0–100；越界配置回落到默认 3，不扩张持久协议。恢复不再因扩展名或隐藏目录过滤而漏发已索引文件；未索引文件始终不参与发送。恢复遇到超过 100 个声明时保留不完整标记，即使再次重启也不会报告全部已发送。

## 继续保留的能力及原因

| 能力 | 当前依据 | 重新考虑的条件 |
|---|---|---|
| 手机原生计划管理 | 不是重复实现调度器，而是绑定原生计划的归属、授权和结果回传；已有真实宿主 smoke 验证 | 用户明确不再从手机创建或管理计划，再整体移除桥接及绑定 |
| 文档正文提取 | 当前通道仍负责将正文送入模型，没有已接入的宿主统一文档读取能力；仅给路径可能使未配置读文件工具的 preset 无法处理文档 | 宿主能稳定提供统一文档读取能力，再删除本地解析 |
| 事件失败后的轮询 | 兼容事件服务缺失或注册失败，已有失败恢复测试 | 明确提高宿主能力下限，并验证缺事件时应拒绝启动 |
| 两种额度存储后端 | 宿主域已有记录按 key 延迟读取，没有全表枚举接口；直接删除会重置现有额度或旧会话编号 | 先获得可靠的数据导出/迁移接口，再合并到单一持久副本 |
| 桌面热更新和授权 UI | 包含配对、撤权与停止自动附件等运行中操作；只读状态无法替代 | 用户接受统一通过配置重启操作后再删编辑器 |
| `/status` 与 `/tasks` | 当前状态与历史索引是不同查询，已共用状态渲染和数据源；合并命令几乎不减少内部逻辑 | 真实使用证明某个入口无用 |
| `/files` 与 `/resend` | 一个查询、一个发送副作用；共享取回路径和安全实现 | 用户明确偏好复合语法，再调整命令入口 |
| `current` / `max` 会话字段 | 升级前可能已回到较旧会话；继续当前会话和分配未使用编号需要两个值 | 将来做有明确收益的路由状态版本迁移 |

这些边界下，继续删除上述能力会引入行为退化或迁移成本，当前没有相应收益证据。无需继续为减少行数而调整持久状态、安全检查、队列或宿主交互。
